Interactive Intern Study Guide

The Input-Process-Output Cycle (Slide 9)

An API operates as a nervous pathway. The server takes input (Sensory stimulation/JSON body), processes it through rules (Gatekeeper validation), and responds with an Output signal (Actuation/Status code).

Key Metaphor: The eye captures the image (Input), the brain cortex runs logic (Process), and the muscle reacts (Output). Try sending a POST to trigger validation checks!

RESTful Naming Conventions (Slide 12)

Proper APIs name resources as nouns (entities) and use standard HTTP methods as verbs. Methods must be consistent:

  • GET /api/neurons - Retrieves lists (Safe, idempotent)
  • POST /api/neurons - Creates a neuron (Unsafe, non-idempotent)
  • PUT /api/neurons/:id - Replaces/Updates a neuron (Idempotent update)
  • DELETE /api/neurons/:id - Removes a neuron (Idempotent removal)

Communicating State (Slide 13 & 14)

Never leave the client guessing. Use proper HTTP response codes:

201 Created Successfully registered new entity. 204 No Content Deleted resource successfully. No body. 400 Bad Request Syntactic/Semantic rule validation failure. 429 Too Many Requests Rate limits exceeded. Rate controller intervention. 500 Internal Error Internal failure. Database crash simulated.

Autonomic Defenses (Slide 15)

Shield your application's logic with core safety checks:

  • AuthN (Authentication): Verifies identity (token validation)
  • AuthZ (Authorization): Verifies operational privileges (role-based)
  • Circuit Breaker: Isolates server failures automatically so system remains stable. Toggling database offline simulates this behavior.
